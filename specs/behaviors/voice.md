# Durable contextual voice conversations

## Scope and principles

The personal workspace uses an application-owned voice interface; Vapi owns live response generation. API admission, account ownership, durable messages, ordered application events and recovery remain application responsibilities. Browser captions and media events never authorize finalized transcript writes. Voice creates no text generation job and cannot make the Gemini worker answer a turn already handled by Vapi.

Follow the architecture's durable-history, personal-ownership, explicit-provider and honest-evidence principles. Keep the existing text flow usable when voice configuration, microphone permission or the provider is unavailable. Preserve existing Convex/widget data and saved provider resources. Use the existing free Vapi account without purchases, upgrades, auto-reload or phone provisioning.

## Provider contract capability gate

Before broad implementation, a short isolated free-account call must establish server-created web-call joining, authenticated callbacks from a dedicated saved assistant, seeded-context representation, committed snapshot ordering and final-report cutoff behavior. A balance label is not a failed-call result. If the real attempt is unavailable, record its safe actual result; deterministic fixtures cannot establish the missing provider capability.

Vapi's documented `conversation-update` contains current committed history, including raw message records and an OpenAI-formatted representation. The dedicated call explicitly sets `modelOutputInMessagesEnabled: false`, so durable assistant history uses transcription of spoken audio rather than unspoken generated model output. Raw user/bot records carry timing fields but have no documented stable message UUID or uniqueness guarantee. Do not invent a stable provider turn ID from transcript text or assume timestamps are unique. The OpenAI-formatted representation is model context, not independent proof of what audio was spoken.

The proposed seed boundary is a unique private system message after the complete prior context. The adapter must prove whether/how that boundary appears in the raw committed message list and formatted context. Raw timed records are the preferred source of current-call transcript and interruption cutoffs; formatted context may establish seed correspondence, but cannot silently substitute an unverified transcript representation. If the exact provider format does not establish an unambiguous seed/live boundary and cumulative ordering, fail closed and review this adapter contract before implementing a different mapping. No caller can enable a fake capability flag. The first successful contract probe records the supported representation and representative synthetic event evidence without committing private captures.

## Admission and context

A verified personal account can start voice only on an owned active conversation without another pending/running text or voice operation. Use the existing transactional account/request idempotency and one-active-operation fence. A voice operation has no fabricated text input/assistant placeholders and no text job handoff. The voice session identity is the operation UUID.

Starting supplies one account-scoped request UUID. Exact replay returns the same session and current state, including a connection capability only when still usable. Reusing the UUID for another command/conversation conflicts. Uncertain browser delivery retains that UUID; checking delivery never creates a second provider call. Ending is idempotent. An explicit later start uses a fresh UUID only after the previous session is terminal.

Capture all completed messages in sequence, including prior voice turns, under the admission lock. The seed is immutable for this session. Enforce the existing 100-message/64,000-Unicode-code-point context bounds and any verified provider serialization limit before creating a call; never summarize, omit older messages or silently truncate. System instructions and the private seed/live boundary are not durable user/assistant turns. A new provider call after reopening receives the same complete ordered completed history plus subsequently finalized turns.

A persisted create-attempt claim permits at most one external creation attempt for a session. Do not hold the database transaction open across provider HTTP. Bound creation at 10 seconds with no automatic HTTP retry. A timeout/lost response is an uncertain external result, not proof that no call exists; exact replay, background recovery and process restart must not repeat a claimed creation attempt. Unclaimed expired attempts are interrupted rather than created later in the background. Do not bind an unknown call based only on a caller-supplied session UUID, metadata or call name.

Register exactly one provider call ID against the admitted session before accepting its transcript. A callback racing that registration is rejected as unregistered and writes nothing; do not depend on provider webhook retries. Once registration completes, authenticated provider retrieval reconciles missed history. A usable join capability is returned only after registration commits. Do not return private configuration, seeded history, webhook credentials or provider control URLs to the browser.

## Session lifetime and ending

Application session states are `starting`, `active`, `ending`, `ended`, `failed` and `interrupted`. Pending/running operation state remains the common admission fence; terminal session and operation changes commit with their application events. A provider progress event cannot reopen or regress a terminal session.

Slice 1 configures a 30-second provider join timeout and a maximum 300-second call. The application has an eight-minute absolute admission deadline, covering creation/join/call bounds and reconciliation slack. These are explicit bounds, not an automatically renewed lease. An expired session cannot join or generate a replacement call through replay.

Stop, navigation, sign-out and browser media loss stop local media immediately and request idempotent server ending when authentication remains usable. The server requests provider termination using only the registered call; it does not trust the browser's claim that the call ended. A provider-confirmed end remains fenced while final history reconciles, for at most 120 seconds. If provider liveness is uncertain, retain the fence until provider termination is confirmed or the absolute session deadline passes; a short reconciliation grace never permits overlapping calls.

A bounded server reconciler checks registered stale/ending sessions and recovers them after API restart. It may retrieve the known call and request its end, but never creates another paid call. At most ten sessions are considered per pass, with at most two concurrent provider requests, five-second read/control deadlines and a five-second minimum pass interval. Shutdown stops new reconciliation intake and drains within the existing service deadline.

A valid terminal report or ended-call retrieval finalizes available authoritative history and releases admission atomically. A definitive creation failure becomes `failed` with a safe failure code. Confirmed end without usable final history after grace, unknown creation/liveness at the absolute deadline, or unrecoverable transcript protocol failure becomes visibly `interrupted`; already completed history remains intact. A retained unsealed tail may be recorded once as interrupted, never falsely completed. A callback after the session's terminal cutoff can acknowledge a duplicate/stale delivery but cannot append, rewrite or reorder history, reopen admission or affect a newer operation.

## Trusted transcript reconciliation and identity

The provider adapter produces an application-owned ordered current-session snapshot after unambiguously excluding seeded context, provider instructions, system/tool messages and empty draft placeholders. Normalize raw `bot`/`assistant` to application `assistant`, and `user` to `user`; never use the browser's role mapping or raw flattened transcript string as final authority. A provider greeting after the boundary is a new assistant turn. Consecutive equal text, equal roles or equal timestamps do not collapse distinct entries.

The session owns stable one-based turn ordinals. Allocate one stable application delivery/message identity for each ordinal when first persisted; identity is session plus ordinal, while role/content hashes check consistency. Content hashes alone and timestamps alone are not turn identities. Persist the ordinal mapping so callbacks, retrieval, process restarts and final reports reuse it.

Treat the last conversational entry of a nonterminal snapshot as an unsealed tail: it can still grow or be cut by an interruption. Only entries followed by another conversational entry are candidates for completed persistence. A valid terminal report/retrieval seals its final tail according to the provider's verified final cutoff. A shorter/incompatible terminal artifact is not complete finalization evidence; retain ending/reconciliation until a compatible authoritative record or the explicit recovery cutoff. Provisional browser text must not fill a missing final entry. For voice, a completed message means the provider-committed spoken utterance, not that the entire planned model answer was heard. A barge-in may therefore yield completed cut spoken text; never append its unspoken generated remainder. Optional `user-interrupted.turnId`/`model-output.turnId` may discard provisional output, but they do not identify all durable user/assistant transcript turns. A tail without a verified spoken cutoff remains provisional or becomes interrupted on recovery, never guessed complete.

Maintain a monotonically growing sealed prefix. A longer compatible snapshot appends only newly sealed turns, in order. Repeated snapshots append nothing; shorter/out-of-order snapshots cannot remove or overwrite sealed turns. A shorter snapshot's old mutable tail may differ from the subsequently sealed text and is ignored as stale. A snapshot extending beyond the sealed prefix must match every already sealed role/content pair; contradictory changes cannot overwrite completed history and produce a safe protocol failure/reconciliation state. An unsealed tail can change without allocating duplicate durable turns; it remains provisional and cannot enter future completed context until sealed.

Commit new finalized turns, their stable receipt/ordinal identities, session progress and ordered outbox events in one owned transaction. Callback acknowledgement follows that commit. All callbacks/reconciliation/end/deadline paths serialize with operation admission and each other. A stale callback or recovery token cannot finalize a newer session. Existing final-message/history/outbox helpers may be deepened for transactional reuse; do not create a second write protocol or bypass the session fence with the generic trusted adapter seam.

## Authentication, configuration and bounds

The application server uses the private Vapi key; the browser receives only the configured public key and short-lived session connection capability. A dedicated saved assistant owns the fixed HTTPS callback URL and dedicated bearer credential. Request-level model/context overrides never supply or replace a server URL/credential. Preserve earlier assistants, credentials and organization settings. Record only the dedicated resource IDs in ignored operator configuration.

The callback route verifies a separate high-entropy `Authorization: Bearer` secret in constant time before processing provider data. Clerk, Vapi public/private and metrics/internal credentials cannot substitute for it. Require the configured assistant and registered call association; unknown/mismatched calls cannot mutate history. Provider credentials grant no product-route or internal realtime access. Authenticated informational event types outside the supported transcript/lifecycle set may be acknowledged without mutation; recognized malformed events fail safely.

Callback JSON is bounded to 4 MiB on that route only. Normalize at most 100 current-call conversational turns and 64,000 Unicode code points in total; each persisted message retains the existing 64,000-code-point output bound. Over-limit/unsupported history is explicit and never silently cropped. Other routes keep their current input bounds. Raw callback/artifact bodies, audio/recording URLs and arbitrary provider objects are never retained as operational diagnostics or exported into common contracts.

Provider API requests use a fixed trusted API origin, no redirects and bounded deadlines. Live-call control capabilities stay server-only and must be validated as HTTPS provider destinations before use; arbitrary callback/browser URLs cannot become SSRF targets. Browser join capabilities are validated HTTPS WebRTC-provider destinations, short-lived and never logged or persisted in browser storage. Do not enable recording, video, tools, handoffs or telemetry features to satisfy this slice.

## Workspace behavior and cleanup

Text mode never asks for microphone permission. Voice starts only from an explicit user action, after microphone permission succeeds; denial creates no provider call/admission and leaves text usable. Voice states visibly distinguish requesting permission, starting, listening/active, assistant speaking, ending/reconciling, ended, denied and safe failure/interruption. Captions are clearly provisional until the server's durable message event replaces them; they are not duplicate history rows.

Only one local voice adapter instance may connect at once. While a voice intent is unresolved or a session is active/ending, text admission and another voice start are disabled; draft editing and history reading remain usable. Existing voice sessions discovered on reload expose Stop/Check status rather than silently creating or joining another call. Failed voice sessions resume through a new controlled call after terminal state, never through text-worker retry.

Keep voice intent UUIDs account/conversation-scoped alongside the existing bounded pending-delivery store. Do not store transcripts, tokens, call URLs or private configuration there. Lost acknowledgements preserve the same intent across reload; account changes fence late callbacks/promises and clear the old account's visible captions/media/state.

Stop/unmount/navigation/sign-out releases listeners, timers, audio elements, owned media tracks and provider resources with bounded waits, even during permission/join failure or a late async resolution. Browser callback epochs prevent an old call from altering a new selection. SDK/provider exceptions map to closed application error categories and never reach UI text, console, telemetry or unhandled-rejection capture as raw payloads. A client dependency that logs raw errors needs a scoped reviewed correction or a safer adapter implementation; global console interception is not a privacy boundary.

## Diagnostics and acceptance

Extend existing allowlisted logs, trace stages, route categories and bounded metrics for admission, provider create, ingestion, ending and reconciliation. Correlate with internal operation/conversation/message/request IDs. Do not log provider call/join/control URLs, callback secrets, raw SDK errors, seed marker/content, titles, transcripts or generated text; no dynamic IDs become metric labels. Missing provider/collector telemetry cannot repeat voice generation or change durable state.

Deterministic tests cover ownership/authentication, create-attempt races and uncertainty, text/voice exclusion, full seeded context, greetings/repeated utterances, mutable tail/interruption cutoffs, duplicates/out-of-order/late callbacks, terminal/deadline/restart recovery, transactional outbox/identity invariants, provider/browser cleanup and privacy. Existing text/realtime/workspace/regression gates remain required. Live acceptance separately proves a free-account call, authenticated durable callbacks, reload/reopen/new-call context and usable text after microphone denial/provider failure. Production deployment remains #26; synthetic or local proof never claims deployed acceptance.

## Primary references and verification limits

- [Vapi server events](https://docs.vapi.ai/server-url/events) documents committed conversation updates, informational lifecycle notifications and final artifacts. It does not document stable unique turn IDs or an immutable whole-history prefix; the mutable-tail mapping therefore requires the real capability probe.
- [Create Call](https://docs.vapi.ai/api-reference/calls/create) documents private-key call creation, Daily web transport and initial model messages. Installed `@vapi-ai/web` 2.5.2 source exposes joining an existing web-call URL with `reconnect`; private server creation compatibility remains a real-call check.
- [Server authentication](https://docs.vapi.ai/server-url/server-authentication) documents saved-resource credential attachment and withholding credentials when a request supplies the server URL. The dedicated saved configuration is mandatory.
- [Assistant settings](https://docs.vapi.ai/api-reference/assistants/update) documents `modelOutputInMessagesEnabled`; explicitly disabling it selects speech transcription rather than generated output. Optional interruption/model-output IDs correlate LLM output, not every transcript entry.
- [Customer join timeout](https://docs.vapi.ai/calls/customer-join-timeout) documents bounded web-call join timeout configuration.
- [Live call control](https://docs.vapi.ai/calls/call-features) documents server control capabilities, provider-selected control hosts and optional public-key authentication. The capability is private application state, not a browser API field.
